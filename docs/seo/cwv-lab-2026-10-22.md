# Core Web Vitals: lab baseline and the first optimisation pass (2026-10-22)

Field data does not exist for this domain yet. CrUX reports no data for any page
(traffic is a few clicks a day), so these numbers are lab measurements, not what
Google scores. The lab numbers matter anyway: they are the ceiling the field
numbers can reach once traffic arrives.

## Method

Chrome DevTools performance trace against production, one page at a time:

- Viewport 390x844 at DPR 3, mobile, touch
- CPU throttle 4x
- Network `Fast 4G` (1.6 Mbps, 150 ms RTT, the same profile Lighthouse mobile uses) and `Slow 4G` (400 kbps, 400 ms RTT)
- HTTP cache bypassed on every run
- CLS read from the trace, LCP from the trace's LCP breakdown

Re-measure with the same settings, because a single run moves by 10 to 30 percent:

```
open the page in Chrome DevTools
toggle device toolbar: 390 x 844, DPR 3, mobile
Performance panel, CPU 4x slowdown, network Fast 4G, disable cache, reload
```

## Before and after

`before` is a single run per page on 2026-10-22, `after` is the median of three
runs on the same day after the change. Single-run numbers carry noise, so treat
differences under about 100 ms as unproven.

| Page | Network | LCP before | LCP after | CLS after |
|---|---|---|---|---|
| `/` | Fast 4G | 1310 ms | **1189 ms** | 0.00 |
| `/reviews` | Fast 4G | 757 ms | **607 ms** | 0.00 |
| `/upcoming` | Fast 4G | 722 ms | 591 ms | 0.00 |
| `/` | Slow 4G | 2080 ms | **1926 ms** | 0.00 to 0.04 |
| `/reviews/peddi-2026-review` | Slow 4G | 1538 ms | 1525 ms | 0.02 to 0.05 |
| `/movies/1057265` | Slow 4G | 1668 ms | 1635 ms | 0.00 to 0.03 |

All three metrics sit in the good band (LCP under 2.5 s, CLS under 0.1). INP has
no field data and no long tasks were visible in the traces.

## What changed

1. **GSAP left the public homepage.** The hero slider imported the whole GSAP
   bundle (71.65 kB raw, 28.2 kB gzipped, the only JS chunk on the page) to tween
   `scrollLeft` once every six seconds. It is now `scrollTo({ behavior: "smooth" })`,
   which the browser runs on the compositor. The replacement is 1.3 kB inline
   (0.6 kB gzipped). The homepage now ships **no JavaScript bundle at all**.
   `gsap` was removed from `package.json`, it had no other importer.
2. **The eight homepage TMDB feeds run concurrently.** They were eight sequential
   awaits, so a cold in-memory cache paid for eight round trips before the first
   byte of HTML. Measured against the live TMDB API from here: sequential 2478 ms,
   `Promise.all` 240 ms. That is about 2.2 s saved on every cold render (the cache
   is one hour, so once per hour per worker; warm renders were already 13 to 17 ms
   locally). Every call keeps its own `.catch(() => [])`.
3. **The artwork origin is preconnected.** `<link rel="preconnect">` plus
   `dns-prefetch` for `image.tmdb.org` now precede the LCP preload. The LCP image
   is a 175 kB JPEG on that origin, so the TLS handshake was previously starting
   only when the preload was parsed. Emitted only on pages that actually reference
   TMDB art.
4. **Responsive images.** `srcset` plus `sizes` on the hero backdrop (w780 and
   w1280), poster tiles and review cards, and `imagesrcset` on the head preload so
   the browser preloads the candidate it will actually paint. A DPR2 phone now
   takes the 780 px file instead of the 1280 px one. Intrinsic `width` and `height`
   are unchanged everywhere, which is why CLS did not move.
5. **Hero dots meet the 24 px target size.** Lighthouse had been failing
   `target-size` on ten 14x14 links. The dot stays 14 px visually, the link box is
   24x24. Accessibility is now 100 with no failed audits (SEO 100, best practices
   100).

## What is left, in order of value

- **Self-host the two font families.** The page still opens connections to
  `fonts.googleapis.com` and `fonts.gstatic.com`. Self-hosted woff2 with a preload
  removes two origins from the critical path and stops a third-party request per
  visit. Not done here because the font URL is per-brand settings, so it needs a
  brand-by-brand decision.
- **The discovery featured band and carousel still request w1280 art** for slots
  narrower than that. A `srcset` there is the next image win.
- **TMDB serves JPEG only.** A local image proxy (AVIF or WebP, re-encoded on
  first request) would cut the LCP image by roughly half. It is real infrastructure,
  not a markup change, so it is a separate decision.
- **Field data needs traffic, and a PageSpeed API key.** Once there is traffic,
  CrUX becomes the signal that counts. `scripts/seo/cwv-baseline.mjs` captures PSI
  snapshots and diffs them for regressions, but it needs `PSI_API_KEY` in the
  environment: Google's anonymous tier answers 429.

## Regression rule

Before shipping anything that touches the homepage hero, the head, or the image
helpers, run the trace above on `/` and `/reviews` at Fast 4G and compare against
the table. A CLS above 0.1 or an LCP above 2.5 s is a regression, not noise.
